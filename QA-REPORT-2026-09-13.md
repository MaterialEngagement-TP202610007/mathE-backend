## 2. Architecture assumptions confirmed

- Netlify proxies `/api/*` to `https://mathe-backend-1cqc.onrender.com/api/:splat` (`mathE-frontend/netlify.toml`). The browser only sees one origin, so the `auth_token` cookie (HttpOnly, Secure, SameSite=None, path `/`) is first-party. **No cross-site cookie issue.**
- Netlify's proxy cuts requests at ~26 s. Every synchronous request must finish well below that. Questionnaire completion is capped at Lambda 7 s + Gemini feedback 8 s.
- Render free tier sleeps after ~15 min idle; cold start ~50 s.

## 10. School merge and per-school question bank (2026-09-13)

### What changed
- **One row per real school.** MINEDU publishes one row per service (`COD_MOD` = school + level). Services sharing premises (`CODLOCAL`) **and** normalized name (`CEN_EDU`: trim, upper, no accents/punctuation) are merged. Homonymous schools in other premises, different names in the same premises and one `CODINST` spread over several premises stay separate. CSV: 6054 rows → 5939 services → **3999 schools** (1940 services merged, 0 fallback `MOD-<codMod>` keys).
- **School shape:** `{ id, institutionKey, cenEdu, district, address, businessName, levels[], codMods[], createdAt, updatedAt }` (`codMod` and `level` removed). `GET /api/schools` caps `limit` at 50 and accepts `district`. `/auth/me` keeps `school: { id, name }`.
- **Per-school question bank:** `Question.schoolId` (FK, `ON DELETE SET NULL`). Generation stamps the attributed teacher's school; a teacher without school gets `400 "Teacher must belong to a school to generate questions"` before any AI call. Recent-statement dedupe is per school.
- **Questionnaires:** V4/A3/K3 sampled uniformly at random from the student's school bank (previously only the oldest candidates). All-or-nothing: any short style — or no school — means 100% fallback; never mixed.
- **Authorization:** get/approve/reject/delete question → teachers only for their school (`403 "Question does not belong to your school"`). `GET /users/students/by-school/:schoolId`, `GET /results/stats/school/:schoolId[/by-grade]`, and `?schoolId=` on `GET /results` and `GET /ml-dataset` → teachers only their school (`403 "You can only access data from your own school"`). The teacher's school is loaded from the DB, not the JWT. Admins: any.
- **Registration/profile:** `schoolId` required on register (`"Missing School Id"`, `"Invalid School Id"`, `"School not found"`); students/teachers cannot clear it (`400 "Students and teachers must belong to a school"`); changing to another existing school is still allowed.

### Migration `20260913120000_merge_schools_by_institution`
Generated by `pnpm db:school-merge-sql` from `prisma/data/schools.generated.ts`, applied automatically by `prisma migrate deploy` (Render `start.sh`). In one migration: add + backfill `Question.schoolId` from the author's school → set `institutionKey` from the embedded `codMod → key` mapping (unmapped rows: `'MOD-' || codMod`) → aggregate `levels`/`codMods` onto the lowest id per key → repoint `User.schoolId` and `Question.schoolId` → delete duplicates → `NOT NULL` + unique key, drop `codMod`/`level`. Works on empty and populated DBs. The SQL is wrapped in an explicit `BEGIN; … COMMIT;` because Prisma 7 does not run PostgreSQL migrations inside a transaction — a failure mid-way leaves the database untouched. Re-verified after adding the transaction: applied with `psql -v ON_ERROR_STOP=1` on a copy of the pre-merge local DB (3999 schools, 2 Claretiano rows, users intact) and with `prisma migrate deploy` on an empty DB.

> **Render:** take a Postgres backup before deploying — the migration is **irreversible**. The seed (`RUN_SEED=true`) upserts by `institutionKey` and is optional.

### Verification
- `pnpm exec tsc --noEmit` ✅ · prisma scripts typecheck ✅ · `pnpm test` ✅ 50 suites / 393 tests.
- Scratch DBs: populated copy, empty DB (migrate + seed twice: 3999 inserted, then 3999 unchanged), and a copy with users on a non-canonical row (users and 89 questions repointed to 1593). `prisma migrate diff` → no drift.
- Local DB: schools 5939 → **3999**; Claretiano 4 → 2 rows (1593 San Miguel `0331041,0336743`, 64 VMT `0825018,1267541`); 3 teachers still on 1593; users on schools 1/50/3782 unchanged (already canonical, 0 repointed); 89/89 questions → school 1 (63 approved); 0 orphan FKs. Seed re-run: 7 updated, 3992 unchanged.
- Against the local DB: a school-1 student got 0 fallback over 20 runs using 60 of 63 approved questions; a school-3782 student → 100% fallback.

## 11. Account activation rules (2026-09-13)

Supersedes B1's "every account starts inactive" and smoke step "Teacher activates a student".

### Rule
- **Students** are active on registration and can log in right away.
- **Teachers** register inactive; only an **ADMIN** can activate them. Teachers can no longer activate anyone.
- Single source of truth: `src/domain/policies/account-activation.policy.ts`.

### Endpoints and messages
| Endpoint | Contract |
|---|---|
| `POST /api/auth/register` | `201` student `{ message: "User created successfully", requiresApproval: false }` · teacher `{ message: "User created successfully. Your teacher account is pending administrator approval.", requiresApproval: true }` |
| `POST /api/auth/login`, `GET /api/auth/me` | `401` inactive teacher: `"Account is inactive. Your teacher account is pending administrator approval."` · other inactive (e.g. soft-deleted): `"Account is inactive. Contact an administrator."` (prefix `Account is inactive` kept for the frontend) |
| `PATCH /api/users/:id/activate` | `roleGuard(ADMIN)` + use-case check. `403 "Insufficient permissions"` non-admin · `404 "User not found"` · `400 "Cannot activate a deleted user"` · `400 "Only teacher accounts require activation"` (student/admin target) · `400 "User is already active"` · `200 { message: "User activated", user }` + `account_activated` notification |
| `GET /api/users/teachers` | Admin only. `page`, `limit`, `isActive=true\|false` (+ shared filters). Items: `PublicUser` + additive `school: { id, name } \| null` (flat `schoolId`/`schoolName` kept, no password) |

### Tests
- Policy, register DTO/use case (student active, teacher inactive), auth controller register response, activate use case (admin OK + notification, 403 non-admin, 400 student/admin target, 400 already active, 404), user routes guards (activate + teachers: admin only), login/me messages, `getTeachers` controller (isActive + school), mapper, `UserRepositoryImpl.findAll` (filters + school include).
- `pnpm exec tsc --noEmit` ✅ · `pnpm test` ✅ 55 suites / 415 tests.

### Follow-ups
- Frontend `StudentsPage` still offers "Activar" for inactive students — the backend now answers `400 "Only teacher accounts require activation"`; remove the action.
- Existing databases may still hold students created inactive under the old rule: run `UPDATE "User" SET "isActive" = true WHERE "roleId" = 3 AND "deletedAt" IS NULL;` once (not needed on the freshly reset local DB).

## 12. Duplicate Claretiano removed (2026-09-13)

Demo decision: students must see only one Claretiano — the demo school **CLARETIANO, SAN MIGUEL** (`LOC-337988-CLARETIANO`, `0331041,0336743`). **CLARETIANO, VILLA MARIA DEL TRIUNFO** (`LOC-347708-CLARETIANO`, `0825018,1267541`) is removed. Only this school.

### Migration `20260913180000_remove_duplicate_claretiano_vmt`
Applied by `prisma migrate deploy` (Render `start.sh`). Wrapped in `BEGIN; … COMMIT;`, matches rows by `institutionKey` (ids differ between environments), idempotent:
- both schools exist → `User.schoolId` and `Question.schoolId` repointed from VMT to San Miguel, then the VMT row is deleted (the only FKs to `School`);
- only VMT exists (unexpected) → row deleted, FKs `ON DELETE SET NULL` clear references;
- VMT absent (empty DB, re-run) → no-op.

### Cannot come back
- `EXCLUDED_INSTITUTION_KEYS` in `prisma/scripts/school-grouping.ts` drops the key when producing schools (new stat `excludedSchools`). `pnpm db:parse-schools` regenerated `prisma/data/schools.generated.ts`: the only diff is the VMT line (CSV 6054 rows → 5939 services → **3998 schools**, 1 excluded). The seed upserts from that file, so it never recreates VMT.
- `pnpm db:school-merge-sql` now refuses to overwrite an existing output file (the applied migration `20260913120000_merge_schools_by_institution`, which must not change) unless `--force` is passed (`prisma/scripts/migration-write-guard.ts`).
