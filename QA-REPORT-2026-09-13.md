## 2. Architecture assumptions confirmed

- Netlify proxies `/api/*` to `https://mathe-backend-1cqc.onrender.com/api/:splat` (`mathE-frontend/netlify.toml`). The browser only sees one origin, so the `auth_token` cookie (HttpOnly, Secure, SameSite=None, path `/`) is first-party. **No cross-site cookie issue.**
- Netlify's proxy cuts requests at ~26 s. Every synchronous request must finish well below that. Questionnaire completion is capped at Lambda 7 s + Gemini feedback 8 s.
- Render free tier sleeps after ~15 min idle; cold start ~50 s.

## 5. Contract verification (frontend ↔ backend)

A full matrix of every frontend HTTP call against backend routes, guards, DTOs and response shapes was produced. After the second fix round:

- Cookies, `/auth/me` shape, `/api` prefix, SSE event name and payloads, generation `count` (query, 1–10, 202), result polling path, VAK enums and 0–100 probability scale: **match**.
- All 18 detected gaps were fixed except the intentional decisions below.

### Intentional decisions / known limitations

| Item | Decision |
|---|---|
| Login response still includes `token` in the body | Kept for Swagger / Bearer tooling. Frontend ignores it. |
| No admin UI in the frontend | Admin activates teachers via Swagger (`PATCH /api/users/:id/activate`) on the Render domain. |
| `GET /questionnaires/:id/answers` shows `vakValue` of already-selected options | Post-answer only; left as-is. |
| SSE state is in-memory | Single Render instance only. |
| Swagger UI public at `/api-docs` | Useful for the demo; gate behind an env flag afterwards. |
| No `helmet` | Deferred (CSP could break Swagger UI). |

## 6. Open risks

| Risk | Impact | Mitigation |
|---|---|---|
| **`gemini-2.5-flash-image` earliest shutdown 2026-10-02** | Question images stop generating (non-fatal: questions saved without image). | If the demo is after that date, migrate the image adapter to the native Gemini image API (`gemini-3.1-flash-image`). |
| Image endpoint `size: 1792x1024` not confirmed by docs | Images may fail silently. | Generate one question in production before the demo. |
| `gemini-3.6-flash` latency vs 8 s feedback timeout | Feedback falls back to predefined text. | Complete one questionnaire in production before the demo; raise `GEMINI_FEEDBACK_TIMEOUT_MS` if needed (keep total < 20 s). |
| Real Lambda payload not verified | Every result silently uses `simple_score`. | `curl` `LAMBDA_URL` and check `classifierType: "xgboost"` on a real result. |
| SSE through the Netlify proxy may be buffered or cut at ~26 s | Toasts delayed. | Reconnect + polling already in place; verify in DevTools on the deployed URL. |
| Render free tier cold start + free Postgres expiry (30 days) | First request slow / DB deleted. | Paid instance or keep-alive ping; check DB creation date. |
| Fallback question bank has no images | Quiz looks plain if AI questions are insufficient. | Approve at least 4 Visual / 3 Auditory / 3 Kinesthetic AI questions. |

## 7. Deployment checklist

### Render (backend, Docker)

- [ ] Runtime: Docker. Health check path: `/api/health`.
- [ ] Web service and Postgres in the same region; `DATABASE_URL` = internal URL.
- [ ] Required env: `DATABASE_URL`, `JWT_SEED` (32+ random chars, `openssl rand -hex 32`), `GEMINI_API_KEY`, `CORS_ORIGIN` (exact Netlify origin, no trailing slash).
- [ ] Set explicitly: `GEMINI_CHAT_MODEL`, `GEMINI_IMAGE_MODEL`, `GEMINI_EMBEDDING_MODEL`, `GEMINI_EMBEDDING_DIMENSIONS`, `LAMBDA_URL`, `SESSION_TTL_HOURS`.
- [ ] Images: `AWS_BUCKET`, `AWS_REGION`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `CLOUDFRONT_DOMAIN`.
- [ ] Optional tuning: `LAMBDA_TIMEOUT_MS`, `GEMINI_*_TIMEOUT_MS`, `QUESTION_MAX_GENERATION_ATTEMPTS`, `QUESTION_GENERATION_CONCURRENCY`.
- [ ] Do not set `PORT` (Render injects it).
- [ ] First deploy only: `RUN_SEED=true`, then set back to `false`.
- [ ] Admin: set `ADMIN_EMAIL`, `ADMIN_PASSWORD` (letters + digits only, min 8), `ADMIN_NAME`, then run `pnpm db:bootstrap-admin` in Render Shell.

### AWS

- [ ] S3 bucket Block Public Access on; bucket policy grants the CloudFront OAC `s3:GetObject`.
- [ ] IAM key has `s3:PutObject` on the bucket.
- [ ] Existing `Question.mediaUrl` rows all start with `CLOUDFRONT_DOMAIN`.
- [ ] Lambda warm-up call right before the demo.

### Netlify (frontend)

- [ ] Build `pnpm run build`, publish `dist`, `NODE_VERSION = 22`.
- [ ] `VITE_API_URL` **unset** (requests go through the `/api` proxy).
- [ ] Proxy target in `netlify.toml` matches the live Render service.
- [ ] "Clear cache and deploy" after any env change.

## 8. Manual smoke test (run on the deployed URLs)

1. `GET https://<netlify-site>/api/health` → `{"status":"ok","db":"up"}`.
2. Refresh a deep link (e.g. `/dashboard/preguntas`) → no 404.
3. Admin logs in via Swagger, activates the demo teacher.
4. Teacher (with a school) logs in → dashboard loads, drawer works on a narrow window.
5. Teacher generates 3 questions → info toast, `question_generated` events in DevTools (EventStream), images render from CloudFront.
6. Teacher approves questions until each VAK style has enough approved questions.
7. Teacher activates a student.
8. Student logs in, starts a questionnaire (AI questions with images), completes it → result page with `classifierType` and feedback source visible.
9. Double-click "Enviar" / refresh during submit → still lands on the result.
10. Log out, log in as a second student in the same browser → no leftover quiz.
11. Wrong password 11 times on one email → Spanish 429 message.
12. Leave the site idle > 15 min (free tier) → splash "Conectando con el servidor…" then normal load.
